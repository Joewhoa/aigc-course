本阶段最该记住的三句

模型的输出当不可信输入处理——加一道代码层守门员，不过就拦下来。
安全判断不交给模型，校验标准也不交给模型。

并行之前先判断依赖。 有依赖只能串行；依赖判断错了，并行只会更快地出错。

容器化 = 可复现 ＋ 隔离；但别把 Docker 当绝对安全。
venv 隔离依赖、容器隔离运行、microVM 隔离硬件——选哪档看输入可不可信。

📌 追加：容器化（5.10）与「不考手写」的关系

「写法也学习一下」，这与「不考手写代码」不冲突，原因是：

Python 编程 Dockerfile
是什么 编程语言（if / 循环 / 函数 / 面向对象） 声明式清单（没有逻辑分支，只有一串「做什么」）
AI 写它 可靠但要调试 照着补全即可，几乎不会错
你要会什么 ❌ 不需要（分工是 AI 写） ✅ 看得懂 ＋ 能验收 ＋ 能指出毛病
类比 —— 采购清单（谁都能读懂）

所以 5.10 的定位是：「看得懂、能验收、能跟 AI 对话」，
不是「能从零手写一个生产级镜像」。这条口径要记住——
出题时考的是「这份 Dockerfile 有什么问题」，不是「默写 Dockerfile」。

⚠️ 与 5.8 的连贯记忆：5.8 讲「venv 只隔离包依赖、不是沙盒」，
5.10 讲「容器隔离更强但共享内核、microVM 才硬件级」——
这两节是同一条线的三级台阶（依赖隔离 → 运行隔离 → 硬件隔离），别当成两个孤立话题。
