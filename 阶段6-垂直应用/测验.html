二、简答题（每题 1 分，共 8 分｜答到要点就给分）

Q7

① 说出三种行业落地范式，各举一个场景。
② 为什么「客服」和「营销文案」两个场景，用同一套技术的做法完全不同？请各说一个设计重点。

考点：6.5

考点：6.5。① 三种范式（缺一扣分）：
· 知识问答类：把文档做成能对话的助手（客服、内部制度、产品手册）—— 技术栈 RAG（阶段 2）
· 流程自动化类：把重复的多步操作交出去（报表、数据清洗、审批流）—— Agent + 工具调用（阶段 3）
· 内容生成类：批量产出文案 / 图片 / 代码（营销、设计）—— Prompt 工程（阶段 1）+ 工具
② 两个场景的设计重点：
· 客服：答错的代价大 → 约束边界，宁可说不知道；涉及退款这类不可逆操作要 高风险确认
· 营销文案：太无聊就失败 → 温度调高、允许发散
核心认知：同一套技术、五种做法——不是技术不同，是取舍不同；区别在于「哪些环节绝对不能出错」。
Q8

① 一个新场景要从 0 做到能用，大致有哪五步？请按顺序写出来。
② 哪两步最容易翻车？为什么？

考点：6.4

考点：6.4。① 五步（顺序必须对）：
找场景 → 定指标 → 选手段 → 小范围试 → 迭代
· ① 找场景：别选「模型本身就能做」的题，要选有私有数据 / 有具体流程的
· ② 定指标：老板要的是「省了多少人力」，不是「准确率 95%」
· ③ 选手段：回到阶段 0 的五问表（Prompt / RAG / Agent / 微调）——且有递进顺序（见 Q11）
· ④ 小范围试：先在一个小场景验证，别一上来全公司推
· ⑤ 迭代：用阶段 5 的评测集 + 可观测性持续改进
② 最容易翻车：第 1 步和第 2 步。
理由：技术都对，但选错场景或指标，项目就没有价值（后面三步技术再对也救不回来）。
Q9

① MCP 是什么？（可用一个类比说明）
② A2A 是什么？它和 MCP 的分工是怎样的？

考点：6.3

考点：6.3。① MCP（要点，缺一扣分）：
· 全称 Model Context Protocol；解决工具接入碎片化（接口不统一，每接一个重写一遍）
· 类比：USB 接口——以前每个设备插口不一样，现在统一标准口，谁都能插
· 一句话价值：一次接好，到处能用（工具能被复用）
② A2A 及分工（要点）：
· 全称 Agent to Agent；解决 Agent 之间协作碎片化
· 关键机制：Agent Card（智能体名片）——声明「我能做什么、需要你提供什么、我是谁」；
　外加 任务生命周期（拆成有状态的过程）、不透明协作（对方不需要知道我内部怎么实现）
· 分工口诀：MCP 让 Agent 会用工具，A2A 让 Agent 会找同行——一个接「物」，一个接「Agent」
Q10

① Computer Use（会操作电脑的 Agent）是怎么工作的？它和你学过的哪个机制是同一套？
② 既然它风险特别高，为什么还要用它？什么情况下才该用？

考点：6.7

考点：6.7。① 怎么工作 + 它是什么机制：
· 四步循环：截屏（看）→ 决定（想）→ 操作（点/输）→ 再截屏（确认）
· 它就是阶段 3 的 ReAct 循环，只是「观察」从文字换成了截图——机制没变，换的是输入形式
② 为什么还要用 / 什么时候用（要点）：
· 因为大量系统真的没有 API（老的内部系统、别人的产品、只有网页版的工具）
· 判断顺序（关键）：先问「有 API 吗」→ 有就用 API；没有再问「量大、重复、值得自动化吗」→ 是才上 CUA
· 配套必须有：高风险动作前人工确认（它能点任何东西，包括「确认付款」）
Q11

① 选技术手段有哪三步递进？为什么是这个顺序？
② 为什么说「自主 Agent 不是更高级，是更不可控」？

考点：6.5

考点：6.5。① 三步递进（顺序错即扣）：
先优化提示词 → 再考虑工作流 → 最后才引入自主 Agent
· 为什么是这个顺序：按「可控性高 → 可控性低」排。提示词最可控、成本最低；工作流步骤写死；Agent 自己决定，最不可控也最贵。
② 为什么「Agent 不是更高级，是更不可控」：
因为它会多带一整套工程负担——护栏（阶段 3）、输出校验（阶段 5）、可观测性、评测集、容错设计。
能用工作流解决的，就不要用 Agent。
面试话术：「我选手段是有顺序的，Agent 不是更高级，是更不可控——能用工作流解决的，我不用 Agent。」
Q12

① LangChain / LlamaIndex 这类框架，各自大致解决什么问题？（只需说定位，不必说 API）
② 什么情况下你会考虑用框架？什么情况下你不会用？

考点：6.8

考点：6.8。① 定位（只说定位，不必说 API）：
· LangChain / LangGraph：把模型、工具、记忆、流程串成一条链 / 图 → 组件多、流程复杂、想可视化编排时
· LlamaIndex：专做检索那一块 → 痛点主要是「检索效果不好」时
· Dify / n8n 等低代码平台：可视化拖拽搭应用 → 想给业务方一个能自己改的东西
· CrewAI 等多 Agent 编排框架：现成封装多 Agent 的角色分工 → 要做阶段 4 那套但不想自己搭
② 值得 / 不值得（要点）：
值得：① 组件多、流程长（重复搭建成本已超过抽象成本）｜② 需要可视化编排｜③ 团队要复用、一致写法
不值得：① 流程简单、组件很少（比如就一个 RAG 问答）——框架解决的痛你根本没有｜② 需求还在快速变（抽象会限制你怎么改）｜③ 出问题要查（多一层抽象 = 多一个盲区）
教材立场：「直接的 API 调用优于复杂的框架」「每多一层抽象都会成为以后调试时新的盲区」
Q13

面试官问：「你看过一个用了框架的项目，你会先问它什么？」
请说出你的验收问题和理由。

考点：6.9

考点：6.8。核心是「先问它替我省了什么」，而不是先看它用了什么。
三个验收问题（要点）：
① 「它具体省掉了什么？」 —— 说不出具体好处 = 可能只是为了显得专业而上的（框架滥用头号原因）
② 「出问题怎么排查？」 —— 要能顺着直接看它调用了什么，而不是猜框架内部逻辑
③ 「换个框架要改多少？」 —— 改得多 = 被框架绑住了，这就是抽象层盲区的代价
⚠️ 反面例子（要点）：如果对方的理由是「它生态好、社区活跃」——这个理由不够，
因为那说的是框架本身，不是它对你这个项目解决了什么。
加分：能补一句教材原话「学会某个具体框架的用法并不重要，重要的是它能否用尽可能少的抽象层让你专注业务逻辑」。
Q14

面试官问：「你觉得未来 1–2 年 AI 的竞争力会往哪走？」
请给出回答，要体现出你对「行业趋势」的判断。

考点：6.2 / 6.9

考点：6.2 / 6.9。答案的落点（这是行业趋势判断，不是技术罗列）：
· 行业正在从「能做事」向「可靠地做事」转变（教材-319）
· 模型能力已经够用了——决定差距的，是它能不能被稳稳当当地放进真实业务里
· 而决定「稳不稳」的，是 Harness 工程（阶段 3 护栏 ＋ 阶段 5 可观测 ＋ 输出校验）
· 结论：竞争力会从「会调模型」转向「会做可靠性工程」
面试话术：「我觉得瓶颈不在模型，在工程——模型已经够聪明了，
但把它放进真实业务里、让它不出事，这件事大部分团队还没做好。
所以我认为竞争力会从『会调模型』转向『会做可靠性工程』。」
（要避免：只答「模型会越来越强」——那是通用能力，不是行业判断）
