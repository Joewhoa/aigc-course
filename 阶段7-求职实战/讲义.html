7.1 先纠正一个误区：面试不是在考试

大多数转行的人把面试当成「知识测验」，所以拼命背概念。方向错了。

面试官真正想判断的是三件事：

他想知道 他通过什么判断
你能不能干活 你有没有真的做过东西，细节能不能说清
你懂不懂原理 你知不知道为什么这么选，而不是背了话术
你好不好合作 你遇到不会的问题怎么反应

这三件事里，第一件最重要。 而转行者最大的资产恰恰是「真的做过东西」。

7.2 项目怎么讲：STAR 的 AI 版

讲项目别流水账，按这个结构讲：

段 说什么 关键点
S 背景 要解决什么问题 一句话说清痛点
T 任务 你负责什么 明确边界，别把团队的功劳说成自己的
A 行动 你怎么选的、怎么做的 ⭐ 这段最重要，也是区分层级的地方
R 结果 带来了什么改变 有数字最好（省了多少时间、处理多少量）

A 段为什么最重要

「怎么选的」才是能力。 举例对比：

差的讲法 好的讲法
「我用 RAG 做了个问答助手」 「我先判断资料塞不塞得进上下文；800 页塞不进，才上的 RAG。切块用的是按段落切，因为制度文档结构清晰」
「我写了个脚本处理 Excel」 「百万行数据直接读会爆内存也超 token，所以我没让模型读表，而是让它写代码去算表，模型只负责解释结果」

看出区别了吗：差的讲法在说「做了什么」，好的讲法在说「为什么这么做」。
后者正是前面六个阶段反复训练的东西。

⭐ 你在项目里的真实角色是「审核者」，这句话要主动讲出来

这是你最容易被讲漏、但最值钱的一条。

教材里有两处直接对应这个角色的依据：

出处 原文 对应你的角色
ch5:149 「测试套件提供明确的验收标准」 你做的事就是定验收标准——不是写实现
ch1:529 同一上下文里的模型难发现自身盲区，所以要「提议者 — 审核者」 你站在审核者位置，不是提议者

这意味着你在面试里该怎么讲：

「我的分工是审核者，不是提议者。我负责三件事：
① 定义「做完」是什么样——把需求翻译成可判定的验收条件；
② 让 AI 按这些条件去实现；
③ 独立核对结果——我要求它主动列出哪些没验、哪些验不了，
而不是只看它说『完成了』。

这套做法是有依据的：同一个模型在同一个上下文里很难发现自己的盲区，
所以验收必须由外部证据来做，不能靠模型自己点头。」

这段话为什么强：

  • 它把「不写代码」从缺陷变成了定位——不是「我不会」，是「我的岗位是审核者」；
  • 它有教材依据（提议者—审核者），不是自吹；
  • 它暗含了你会追证据——这正是「有效信号」那套东西。

⚠️ 别硬套：如果对方是个纯工程岗、明确要「能独立写实现的人」，
这不等于你不适合——那是另一个岗位。判断岗位属于哪一层，看 7.8。

7.3 转行怎么解释（这是你的必答题）

面试官一定会问：「你不是这个专业的，为什么觉得自己能做这个？」

三条原则：

  1. 不回避、不道歉。 不要用「虽然我不是科班，但是……」这种示弱句式
  2. 用真实项目当证据。 说「我做过 X」，而不是「我学过 X」
  3. 把原专业变成优势，而不是包袱

第三条怎么理解

转行者的原背景不是空白，很多能力是可迁移的：

原来的能力 迁移到 AI 应用岗
处理过大量杂乱数据 对数据脏、格式乱的敏感度，比纯算法的人强
跟很多客户/部门打过交道 更懂真实需求，不会做出没人用的东西
自己用 AI 工具提过效 是 AI Coding 的早期实践者，不是纸上谈兵

面试话术模板（按自己情况改）：

「我不是科班出身，但我在（原岗位）里实际遇到了（某个具体问题），当时没有现成方案，我就用 AI 把它做出来了——（一句话说结果）。这个过程中我发现，做 AI 应用最难的不是写代码，而是判断该用哪一层手段、怎么验证结果。这两件事我在（原岗位）里天天在做。」

这段话的厉害之处：既承认了转行，又证明了「我做过」，还提出了一个专业判断。

7.4 高频面试题清单（附答题方向）

概念类

问题 答题方向 对应阶段
「模型有记忆吗？」 没有，记忆是外面存的 0
「怎么防幻觉？」 给它材料，不是求它别编 0
「Prompt / RAG / Agent / 微调怎么选？」 说五问表，强调「能往上不往下」 0
「什么是 RAG？」 五步：切块 → 向量化 → 入库 → 检索 → 生成 2
「RAG 和微调的区别？」 RAG 给知识，微调改风格 2
「Agent 和普通调用差在哪？」 多了循环：能看结果再决定下一步 3
「工具调用怎么实现的？」 四步链条，强调模型只出请求 3
「怎么防止 Agent 乱来？」 四道防线 ＋ 兜底在数据层 3

⚠️ 「六步」和「四道防线」被问到时，先做一次桥接

阶段 3 讲义里的六步机制和四道防线是我们自己的教学结构，和教材的通用说法不完全同名。
面试官心里想的通常是他自己熟悉的那套，你不说桥接，他会以为你答偏了。

面试官心里的版本（教材通行说法） 我们的版本（阶段 3） 桥接话术
工具调用四步（ch1:81）：① 上下文里声明工具 → ② 模型决定调不调、调哪个、传什么 → ③ 结果追加回上下文 → ④ 模型据此决定下一步 六步：在四步之外，补上了「静态前缀 + 轨迹」怎么拼、「外层程序怎么执行与校验」 「您说的四步是主循环。我这边习惯拆得更细一点——除了模型和工具之间的四步，还要加上静态前缀怎么组织、轨迹怎么累积、以及外层程序收到请求后的校验和执行。核心逻辑跟您说的是同一个。」
三层护栏（ch1:474）：上下文层 / 执行层 / 数据层，按被绕过的难度排 四道防线（权限最小化 / 高风险确认 / 参数校验 / 轮次成本上限） 「防线讲的是动手那一刻的拦截，属于执行层。但完整的防护是三层——越靠下的层越不依赖模型自己的判断，越难被穿透。所以真正的兜底在数据层，不在执行层。」

为什么要写这一节：这两处不是讲错，是命名不同。
但面试里「命名不同」= 对方听不懂你说的= 丢分。
会做桥接的人，才是真的懂——因为他知道两套说法各自站在什么位置。

工程类

问题 答题方向 对应阶段
「怎么保证输出稳定？」 固定测试用例 + few-shot + 限格式 + 低温度 1
「怎么知道改得更好了？」 评测集重跑、对比通过率 5
「线上出问题怎么查？」 可观测性：记完整输入输出 + 工具轨迹 5
「LLM 应用有什么安全风险？」 提示词注入；安全判断不交给模型 5

场景类

问题 答题方向 对应阶段
「有个 800 页文档问答需求，你怎么做？」 五问表走一遍 → RAG 0/2
「怎么让 Agent 处理一个复杂多步任务？」 规划 + 记忆 + 反思 4
「你怎么看 AI 在 X 行业的应用？」 这个行业哪些环节绝对不能出错 6

7.5 简历怎么写

核心原则：写「成果」和「判断」，不写「技术栈清单」。

差的写法 好的写法
「熟悉 RAG、Agent、Prompt 工程」 「独立完成一个账单核对助手：判断资料规模后选用 TF-IDF 检索（而非向量库），因为账单关键信息是字面匹配的」
「会使用 AI 工具提效」 「把月度数据处理周期从 2 天压缩到 1 天，方法是把逐行循环改成分块处理」

为什么后者强：

  • 有具体的判断（为什么选 TF-IDF 而不是向量库）→ 证明懂原理
  • 有数字（2 天 → 1 天）→ 证明有结果

注意：不要为了好看编项目。面试官会追问细节，编的一问就露。

7.6 面试现场怎么应对不会的问题

三个动作，按顺序：

  1. 先给框架：「这个我具体没做过，但按我的理解，可以从 X 和 Y 两个角度想」
  2. 说清边界：「X 这块我有把握，Y 我不确定」
  3. 给一个可验证的答案：「如果让我做，我会先 Z 验证一下」

绝对不能做的：硬编、糊弄、假装懂。

为什么：面试官最怕的不是你不会，是你不会却说自己会——那意味着以后会在生产环境出事。

回到阶段 3 的「宁可说不知道」——这个原则不只是给 Agent 的，也是给你自己的。

7.7 面试会怎么问（元问题）

面试官问 别这么答 该这么答
「你为什么转行？」 「因为 AI 有前途」 讲具体做了什么，再讲发现了什么判断
「你最大的短板是什么？」 「我太追求完美」 说真实且在改进的短板，比如「工程基础不如科班，我现在用系统的验收条件来补」
「你有什么想问的？」 「没有」 问团队在做什么场景、怎么评测评效——显示你在意怎么把事做好
「你会不会觉得自己经验不够？」 「我会努力学」 用已完成的真实项目回应，别用态度回应

7.8 被要求写代码 / 面试代码题时怎么答（ 新增）

这是你一定会遇到的场景，而且一定会让你难受——因为你确实不手写。

先给结论：

这一节不是教你怎么写代码，是教你「不被这一问打倒」。

🔴 先认清事实：这是岗位分层问题，不是「你行不行」的问题

招聘里那句「精通 Go 或 Python、熟悉 K8s」，对应的就是 infra 层岗位。
你如果投的是应用层（见 7.9），这题不该出现在你的面试里——
它出现，说明你可能投错了层。

所以正确顺序是：先判断这题该不该被问，再决定怎么答。

面试现场的四步应对（真被问了就这么走）

步 说什么 为什么
1. 先反问，不急着答 「我想先确认一下这道题要验的是什么 —— 是我的编码熟练度，还是这个模块的设计思路？」 一句话就把话题从「手速」转到「判断力」。而且这问题本身就展示了工程思维。
2. 说清分工（不遮掩） 「我的工作方式是：代码由 AI 实现，我定验收条件并独立核对结果。这不是回避，是我在团队里的实际定位。」 别假装能手写——面试官能看出来，一露馅全盘崩塌。**坦诚反而可信。
3. 把话题转到你的强项 「如果这题考的是『怎么保证它是对的』——我可以在几分钟内给你一套验收条件：输入长什么样、输出必须满足什么、哪些情况要挡、怎么测。」 这一步是胜负手：你把一道你答不出的题，换成了你最擅长的题。
4. 补上教材依据（加分） 「这套做法的依据是：同一个模型在同一个上下文里很难发现自己的盲区，所以验收要靠外部证据，不能靠它自己说完成了。」 有依据的判断 = 专业的判断。这句 ch1:529。

⚠️ 三个绝对不要做的

❌ 不要 为什么
硬着头皮现场写 写不出来，节奏就断了，后面的题也来不及答——一道题拖垮整场
含糊其辞「我也可以学」 这是在否认自己的核心能力，等于告诉对方「你没有不可替代的东西」
反过来质疑对方 「我觉得手写不重要」——这话只能你自己说，被质疑就不成立了。你可以说「我分工是审核者」，不能说「会手写的人没价值」。

一个重要的区分（这是本节最该记的一条）

该说
✅ 可以说的 「我的定位是审核者，这是我的分工」——陈述事实，讲你的流程和依据
❌ 不该说的 「写代码不重要，会写的人没价值」——这是行业判断，不是你的能力描述

区别在哪：前者在说我怎么做，后者在说这个岗位该怎么做。
面试官问的是「你行不行」，你回答的应该是「我行不行」，不是「这行不行」。

这个区分也是 7.7 那个原则的延伸——所有回答都要落在你能负责的东西上。

7.9 AI 岗位分层：怎么认准方向，别被 K8s 带跑（ 新增）

这节解决一个具体问题：你搜「大模型岗位」时，涌出来的全是 K8s / GPU / 分布式——然后你以为那些是入行门槛。

它们不是。它们是另一层岗位的门槛。

一句判据

这个岗位是「用大模型做业务」，还是「造让大模型能跑起来的东西」？

「用」→ 应用层 ｜ 「造 / 训」→ Infra / 算法层

四层对照表

层 干什么 典型要求 你的匹配
AI 应用 / Agent 工程 用模型做业务：RAG、Agent、Prompt、工作流、评测 Prompt/RAG/Agent、设计能力、验收能力、懂业务 ✅ 这就是你学的全部内容
AI Infra / 推理平台 造让模型跑起来的服务：网关、调度、多租户、GPU 编排 Go/Python 后端、分布式、K8s、gRPC、高并发 ❌ 差得最远
算法 / 训练 训模型、微调、对齐 ML 背景、数学、训练框架 ❌ 完全不同的学科
传统后端 一般业务系统 语言无关，CRUD、架构、数据库 ⚠️ 与你目标不同，别投

为什么你「最近一直看到 K8s」

因为「大模型」的招聘量集中在 infra 平台岗，不在应用岗。

平台岗是一个模型能力商品化之后必然出现的基建需求（谁都想让别人能调模型）；
应用岗是散落在各个业务里的，没有统一标题。

所以：搜「大模型」＝搜到一堆 infra；搜对了词才能看到你的岗。

搜索限定词：大模型应用 / LLM 应用 / Agent 开发 / RAG / AI 工程师（应用方向）
别只搜「大模型」「AI 岗」——搜出来一堆推理平台和算法岗，你会被带跑。

⚠️ 一个真实的陷阱：资深要求被包装进入行门槛

招聘话术里最常见的操作：把「3–5 年经验、做过平台级系统」的要求，写成「熟悉 K8s、有微服务经验」——
读起来像「入行必须会」，实际是「这岗招的是资深」。

你之前读过的那份卖课话术核查，说的就是这个（结论：「真技术 + 焦虑包装」）。

你的判断方法（看 JD 的两条线）：

读到什么 判断
大量篇幅在讲基础设施（网关、调度、GPU、K8s、gRPC、性能调优） 这是 infra 岗，资深向，不要投
篇幅在讲业务场景 + 效果指标（解决什么问题、怎么衡量做得好不好、用什么手段选型） 这才是应用岗，你匹配
「精通」某语言 + 「有大规模生产经验」 资深要求，不是入门要求

最后一条尤其重要：精通 ≠ 会用。 「精通 Go」是招人的理想画像，不是招人的门槛。

面试时怎么用这一节

如果对方问「你为什么不做 infra」：

「我看过 token 平台那类岗位，它的核心是把模型做成可被调用的标准服务——
网关、调度、多租户隔离，那属于模型商品化的基建层。
我做的是把模型用到具体业务里这一层：场景判断、技术选型、结果验收。
这两层我都看得懂区别，我能判断一个需求该用哪一层的手段——这比只会一层更有用。」

这段话的价值：它把「我不会 infra」变成「我知道 infra 和应用的区别，并且我知道需求该落到哪一层」。
后者是资深的信号，前者是短板。

7.10 最后一件事：把七个阶段串成一句话

面试的最后，面试官常常会问「还有别的吗」。这时候你如果能用一句话总结你的方法论，印象分直接拉满：

「我做事有一个固定的判断顺序：先问结果是不是必须精确算（是就用代码），再问内容塞不塞得进上下文（塞得进就写进提示词），塞不进才上检索，要动手才上 Agent，要改风格才考虑微调。 每一步都先定验收条件，再让 AI 实现。」

这一句话串起了阶段 0、1、3 的核心。 背下来。

本阶段要带走的话

  1. 面试不是考试，是判断你能不能干活。 讲「为什么这么选」，比讲「做了什么」值钱。
  2. 你在项目里的角色是「审核者」——这是定位，不是短板。 定验收条件 ＋ 独立核对 ＋ 让 AI 列出没验的。
  3. 转行不是短板，是可迁移经验 + 真实项目的组合。 不道歉、示弱、回避。
  4. 不会就说不会，但要说清边界和验证思路。 这跟教 Agent 的原则是同一个。
  5. 被要求写代码时，先反问「这题要验什么」，把话题从手速转成判断力——别硬写，也别否认自己的核心能力。
  6. 搜岗限定词，认准应用层。 K8s / GPU / 分布式是 infra 岗的门槛，不是你方向的门槛。

学完请去做同目录下的 测验.md。这套题没有标准答案，是模拟面试，答完会逐题点评。
