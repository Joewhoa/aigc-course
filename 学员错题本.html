学员错题本

这份文件是给你（学员）的，不是给教练的。
你的教练 Agent 叫 Scout —— 教学过程中，它会把你卡住的地方、答错的地方、
说「我原来以为…」的地方，一条条记进这份文件。

建议做法：把这份文件（或它的副本）放在你自己的笔记里。
学完 8 个阶段回头看，里面全是你自己踩过的坑 —— 那比标准答案有用得多。

怎么用这份文件

你想做的事 怎么做
开始学之前 不用看，直接从阶段0本章导读.html 开始
学完一阶段 看「阶段总览」那一栏，确认自己走到哪了
卡住的时候 翻 Scout 记下的这几条，看是不是同一个坑
学完 8 个阶段 通读一遍，那些「我原来以为 X，其实 Y」就是你的成长证据

这份文件会自己长大 —— 每一次 Scout 教你一次，它就多一条记录。

我的记录（Scout 自动维护）

⚠️ 这一节由 Scout 写入，你不用手填。
每条记录会写清：你在哪儿卡的 → 你当时怎么想的 → 正确理解是什么。

格式说明（Scout 按这个格式写）

[阶段N · 小节X.Y] 你的问题或题目
你当时说的/做的：
Scout 的回答：正确理解是……
你的原话（如果这是误解）：「我原来以为 ______，其实 ______」
错因类型：概念错 / 调用失败 / 表达不完整

三种错，Scout 会分开标

错因 什么意思 怎么补
概念错 理解反了 回讲义重读那一小节
调用失败 概念答对过，这次没想起来用 不用重读，做一张检查清单提醒自己
表达不完整 意思对，漏了要点 不用重读，重讲一遍并收口就行

还没有记录

Scout 会随着教学自动往这里写。
如果你打开这份文件时这里还是空的 —— 说明还没开始学，或者教练还没配置好。

附：可能遇到的坑（参考，不限于此）

下面是这门课里常见的坑，供你预习用。
但真正属于你的坑，由 Scout 在教学时记进上面那一节 —— 因为你的卡点和别人的不一定一样。

阶段 0 · 基础概念

现象 原因 怎么解决
以为模型有记忆 记忆是外面存的，每次把历史重新发给它 关键结论要写进文件，别指望它记得
以为它在「查资料」 它在生成「最顺的下一句」 想要它说对，就得给它材料
以为答对了就等于懂了 答对但说不出「为什么这么选」= 未掌握 让教练追问一句

阶段 1 · Prompt 工程

现象 原因 怎么解决
加了「不要编造」它照样编 只给了禁止项，没给替代动作 改成「资料未提及就回答『资料未提及』」
每次输出字段名都不一样 没给完整结构示例 给一整条完整范例，不是描述字段
约束写在开头，它还是不听 离生成位置太远 最关键的约束放结尾
十条规则写下去，它还是不懂「礼貌」 规则本身不可判定 换成给三个例子

阶段 2 · RAG

现象 原因 怎么解决
用户问法和原文用词不同，就检索不到 纯关键词检索不认同义 混合检索（关键词 ＋ 向量）
改了文档，检索结果还是旧的 只改文件没重建索引 文档更新与索引重建必须绑成一步
找到 20 段全塞进去，答案反而变差 噪音淹没了信号 限制 top-k（通常 3–5 段）
检索内容递过去了，它还是自己编 没给约束和替代动作 补「只依据给定资料回答 ＋ 资料未提及就明说」
以为微调能让它「记住业务数据」 微调改风格，不注入知识 注入知识用 RAG，改行为才用微调

阶段 3 · Agent 与工具调用

现象 原因 怎么解决
工具选错、参数填错 工具描述写的是「我是什么」而不是「什么时候该选我」 描述里写适用条件 ＋ 给调用例子
它反复调用同一个失败的工具 失败后没给替代路径 错误信息要可执行（告诉它接下来能做什么）
上下文越来越贵、越来越慢 轨迹只增不减 上下文压缩 ＋ 轮次上限
以为换更强的模型能解决「老是选错工具」 选错是描述问题，不是能力问题 先改工具描述，再考虑换模型
它说「做完了」其实没做完 完成只是它的一句宣称 要独立证据（跑一遍测试、看实际输出）

阶段 4 · 多 Agent 协作

现象 原因 怎么解决
几个 Agent 说得几乎一模一样 独立判断变成了同声同气 让它们看不同材料再讨论
分工之后开始互相抵消 目标互斥却没有仲裁机制 指定一个拍板的人，其余提供意见
传话传了三手就变味 每转述一次都在丢信息、 加解释 传路径/产物，不传转述
活干到一半就停了，还说做完了 过早终止：看起来像成功 检查独立证据，不看宣称

阶段 5 · 工程化

⚠️ 这一节的大多数坑发生在具体机器环境上（装环境、配代理、跑 Docker）。
不写代码、只做判断与验收的学员，只需要看最后 3 条 —— 知道「出问题时该往哪个方向怀疑」就够了。

现象 原因 怎么解决
上线后变差，没人发现 没有持续对比 建评测集，每次改动重跑一次
改提示词之后，回滚不回去 提示词和配置没版本记录 提示词也要存版本，和代码一起
「好像好了一点」其实只是噪声 没有对照基线 固定样本重跑，看通过率而不是感觉
模型换版本 / 提示词换版本之后，不知道是哪个引起的变好变坏 三个变量同时动了 记录模型版本 ＋ 提示词版本 ＋ 工具版本
容器就是绝对安全的 容器共享内核 隔离分三档：进程级 / 容器 / microVM；按「输入可不可信」选档

阶段 6 · 垂直应用

现象 原因 怎么解决
没有 API 也上 Computer Use 跳过了最便宜的一步 先问有没有 API，没有再考虑操作界面
流程很简单却上了框架 框架的长期维护成本被低估 流程简单就直接做，框架是最后选项
框架搭的东西坏了查不出原因 抽象层太多，调试变难 每一层抽象都是新的盲区
低代码搭的东西上线后没人管质量 演示容易，维护难 上线前问清：谁维护、怎么发现坏了

阶段 7 · 综合实战

现象 原因 怎么解决
被要求写代码就慌 你的价值不在手写 先反问这道题要验什么 → 说清分工 → 把话题转到强项
讲项目像流水账 只讲了「做了什么」，没讲「为什么这么选」 用 STAR：背景 / 任务 / 行动 / 结果，重点在行动
说的和资料上的说法对不上 同名不同义 主动桥接：「你说的那个意思是…，我这边叫…」
把「资深要求」当「入门门槛」 招聘描述常把两者混写 「精通 X」＋「有大规模生产经验」是招资深，不是入门门槛

这份文件怎么维护

不需要你手动维护。 Scout 会在每次教学后自动更新「我的记录」和「阶段总览」两节。

如果换了新的 AI 对话（记忆丢了），把这份文件发给新对话的教练，它就能接着往下记。
