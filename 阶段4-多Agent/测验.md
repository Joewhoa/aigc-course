## 一、选择题（每题 1 分，共 6 分）

**Q1.** 关于「要不要用多 Agent」，**判断的根本依据**是什么？
> 考点：4.1

- A. 多 Agent 一定比单 Agent 强，能用就用
- B. 协作过程有没有引入单个 Agent 在生成时拿不到的新信息
- C. 只要任务复杂就必须用多 Agent
- D. 看团队预算够不够

---

**Q2.** 「Agent 的故障天生是拜占庭式的」——这句话的意思是？
> 考点：4.1

- A. 它出错时一定会停机报错，很容易发现
- B. 它很少径直停止运行，而是继续给出看似可信的错误结论
- C. 它只会输错密码
- D. 它的错误可以被模型自己审查出来

---

**Q3.** 「主管-下属（管理者模式）」这种拓扑，主管 Agent 的主要职责是什么？
> 考点：4.2

- A. 亲自干所有的活
- B. 拆解任务 + 汇总结果，自己一般不干具体活
- C. 只负责记录日志
- D. 检查代码语法

---

**Q4.** 多 Agent 之间传**大块产物**（比如一份几 MB 的素材），推荐怎么传？
> 考点：4.3.1 / 4.3.3

- A. 把内容全塞进消息里发过去
- B. 放到共享文件系统，传「路径字符串」
- C. 转成自然语言描述一遍
- D. 不传，让接收方自己去猜

---

**Q5.** 虚拟文件系统的**四类区域**里，哪一类是**并发冲突的高发地**？
> 考点：4.3.1

- A. Agent 专属工作区（Scratchpad）
- B. 多 Agent 共享空间
- C. 外部挂载资源（比如网盘）
- D. 系统内置资源（比如 Skills）

---

**Q6.** 主 Agent 想知道子 Agent 的进展，**讲义明确说「不建议」**的做法是哪个？
> 考点：4.3.2

- A. 让子 Agent 到关键节点主动发消息汇报
- B. 约定一个 `progress.md` 进度文件，子 Agent 定期更新
- C. 用「轨迹持久化」——把子 Agent 的全部执行过程实时写文件，主 Agent 读它
- D. 通过消息总线发一条 `status_update`

## 二、简答题（每题 1 分，共 8 分｜答到要点就给分）

**Q7.** 不共享上下文的协作，靠**两个平面**支撑。
请分别说出**数据平面**和**控制平面各管什么**（各一句话），
并说出**控制平面管的是哪四件事**。
> 考点：4.3

---

**Q8.** 多 Agent 之间传消息，为什么要求消息带一个**统一的「信封」**？
信封里至少要有什么？这一条为什么被说是「多 Agent 系统调试的关键」？
> 考点：4.3.2

---

**Q9.** 请说出**「过早终止」的三种形态**，以及它和「循环失控」是什么关系。
再写出讲义里那句**根因**。
> 考点：4.4

---

**Q10.** 关于**反思（Reflection）机制**：为什么「让模型自己审自己」**经常是无效的**？
请说出研究报告的结论，以及**有效反思的两条硬条件**。
> 考点：4.5

---

**Q11.** 记忆的**「记忆层次」**这一套分几层？分别是什么、各存什么？
另外请说出记忆还有**哪两套正交的分类体系**，以及**「工作记忆」指的是什么**。
> 考点：4.5

---

**Q12.** 多 Agent 的**七种失败模式**里，哪一种是「**人的问题、技术解决不了**」？
它包含哪两种具体表现？为什么说这门课存在的意义就是治它？
> 考点：4.4

---

**Q13.** 「**什么时候不该用多 Agent？**」请给出回答，并说出**判据**和一个**反例**。
> 考点：4.1

**要求：成段说，不要分点符号。**

---
