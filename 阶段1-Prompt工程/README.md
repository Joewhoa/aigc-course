# 阶段 1 · Prompt 工程

**核心问题**：怎么把要求说清楚，让它稳定照做？

## 本阶段学什么

| 节 | 内容 |
|---|---|
| 1.1 | 提示词是设计出来的输入，不是聊天 |
| 1.2 | **四段式**：角色 / 任务 / 约束 / 格式 |
| 1.3 | 为什么换个说法结果差很多 |
| 1.4 | **三个必须掌握的写法**（few-shot / 限格式 / 约束边界） |
| 1.5 | 提示词是要被测试的 |
| 1.6 | 拿两个例子过一遍 |
| 1.7 | 章节小测：能答上来才算真会了 |
| 1.8 | **实操**：找出提示词里真正起作用的那一段 |

**附录**（3 份）：
- `附录-上下文工程` —— 行业术语的下一步升级（Prompt 工程 → 上下文工程）
- `附录-JSON最小必读` —— **JSON 是什么、为什么 AI 场景到处是它**
- `附录-JSON补充-从Python对照着看` —— **JSON 和 Python 像不像、差在哪** ＋ 两组验收演练

## 过关标准

- 测验 ≥ 8 分
- 能说清「约束要可判定」——**能写成一个 if 判断的才是约束**
- **能扫出 AI 写的 JSON 里的格式错**（不用会写，要会挑）——见 `附录-JSON补充` 第七节

## 本阶段最该记住的一句

> **只禁止不给替代动作，等于没约束。**「资料未提及」比「不要编造」有用。
