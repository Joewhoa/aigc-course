# 附录 · JSON 补充：从 Python 对照着看

> **为什么有这一节**：读完《JSON 最小必读》之后，很容易冒出一个念头——
> 「JSON 是不是跟 Python 的数组差不多？」
>
> **这个直觉对了一半，而且错的那一半正好是最要紧的一半。**
> 左边先说对在哪：JSON 的 `[ ]` 确实等于 Python 的列表 `[ ]`。
> 右边说漏在哪：JSON 里**最常用**的其实是 `{ }`，而它对应的是 Python 的**字典**。
>
> 所以本节不重复基础，专门做一件事：**把 JSON 放在 Python 旁边逐条对照**，
> 把「哪些能直接套、哪些一用就错」标清楚。

---

## 一、先正面回答：你觉得像数组，对在哪、错在哪

| 你的直觉 | 判定 | 说明 |
|---|---|---|
| 「JSON 跟 Python 的数组类似」 | ⚠️ **对一半** | **JSON 数组 `[ ]` 确实 = Python 列表 `[ ]`**，这半边完全对 |
| 但 JSON 里**最常用**的其实是 `{ }` | 🔴 **这半边漏了** | `{ }` 对应的**不是数组，是 Python 的字典 `{ }`** |

**为什么这一半更要紧**：你去看任何真实的 AI 输出——工具参数、模型返回的结构化结果、记忆的存储格式——
**几乎全是 `{ }` 打头**。数组只是 `{ }` 里面装东西用的容器。

> **记住这句话**：`[ ]` 是「一串」，`{ }` 是「一条」。
> 数组只负责「装多条」，**真正描述「这条信息长什么样」的是 `{ }`**。

**一张图记住两个骨架**：

```
{ }  ← 一条信息（字段名 : 值）      = Python 的 dict（字典）
[ ]  ← 一串东西                     = Python 的 list（列表）
```

---

## 二、逐条对照表（这张表是本节核心）

### 骨架对照

| JSON | Python | 一样吗 | 一句话 |
|---|---|---|---|
| `{ }` 对象 | `dict` 字典 | ✅ 基本一样 | 都是「键 → 值」 |
| `[ ]` 数组 | `list` 列表 | ✅ 基本一样 | 都是「一串，有顺序，可以重复」 |
| （无） | `tuple` 元组 | ⚠️ **JSON 没有** | Python 元组转 JSON 会**自动变成数组** |
| （无） | `set` 集合 | ⚠️ **JSON 没有** | 集合**直接报错**，不能转 JSON |

### 值类型对照

| JSON 写法 | Python 写法 | 备注 |
|---|---|---|
| `"张三"` 字符串 | `"张三"` | **两边都要引号** |
| `30` 数字 | `30` | **两边都不加引号** |
| `3.14` 小数 | `3.14` | 一样 |
| `true` / `false` | `True` / `False` | 🔴 **大小写不同！** JSON 全小写 |
| `null` | `None` | 🔴 **拼写不同** |
| `{ }` | `{ }` | 一样 |
| `[ ]` | `[ ]` | 一样 |
| （无） | `datetime` 日期 | JSON **没有日期类型**，只能写成字符串 |

> ⚠️ **最容易栽的一行**：`true` / `false` / `null`。
> Python 写 `True`，JSON 必须写 `true`；Python 写 `None`，JSON 必须写 `null`。
> **AI 有时会把 Python 习惯带进 JSON 输出**——这是验收时要盯的点之一。

---

## 三、三条「Python 能过、JSON 不行」的差异（最要命）

这三条是 JSON 和「看起来像 JSON 的 Python 写法」的**真正分界线**。
它们的共同根源是：**JSON 是一份跨语言的严格交换格式，容错率为零。**

### ① JSON 的「键」必须是字符串（Python 不用）

```python
# Python 允许
{1: "a"}          # 键是数字，合法

# 但转成 JSON 会被强行改掉：
{"1": "a"}        # 数字 1 变成了字符串 "1"
```

→ **危险在哪**：程序按 `"1"` 去取值，你心里想的是 `1`，**对不上就是静默空值**。

### ② JSON 不允许「结尾多一个逗号」

```json
{ "a": 1, }        ← ❌ 报错：Illegal trailing comma
[ 1, 2, 3, ]       ← ❌ 同样报错
```

→ Python 里 `[1, 2, 3,]` 是合法的，**JSON 里不行**。这是拼接字符串时最高频的错。

### ③ JSON 不允许单引号、不允许注释

```json
{ 'a': 1 }              ← ❌ 报错：Expecting property name enclosed in double quotes
{ "a": 1 }  // 注释      ← ❌ 报错
```

→ Python 里单引号、`#` 注释都随便用；**JSON 只认双引号，且一个注释都不能有**。

### 实测报错长什么样（这就是你要能认出来的东西）

| 你写的 | 程序会报 |
|---|---|
| `{"a": 1,}` 结尾多逗号 | `JSONDecodeError: Illegal trailing comma before end of object` |
| `{'a': 1}` 用单引号 | `JSONDecodeError: Expecting property name enclosed in double quotes` |
| `{"a": 1 // 注释}` 写了注释 | `JSONDecodeError: Expecting ',' delimiter` |

> 📌 **看到 `JSONDecodeError` 就知道**：不是逻辑错，是**格式没写对**。
> 这三个词是验收时的信号灯 —— 出现即退回，不用往下查逻辑。

## 四、那为什么非要用 JSON，直接用 Python 的写法不行吗

**不行，原因就一条：Python 的写法只有 Python 认识。**

| | Python 的字面量 | JSON |
|---|---|---|
| 谁认识 | **只有 Python** | **几乎所有语言**（Python / JS / Java / Go…） |
| 严格程度 | 宽松（容忍单引号、尾逗号） | **严格到零容忍** |
| 定位 | 写给人看的代码 | **写给程序之间传递数据** |

**关键**：AI 模型**不是 Python 程序**。它吐出的是**文本**。
你要求它「按 JSON 输出」，等于给它一套**所有语言都认的通用格式**——
这样无论是 Python、JS 还是别的程序来接，**都能可靠地取出字段**。

> 资料里说得直接：
> 「每个工具通过 **JSON Schema** 定义输入参数的类型、约束和描述，
> **确保不同的客户端都能正确理解工具的使用方式**。」
>
> 这句话把 JSON 的定位讲死了：**它是「通用接口」，不是「一种编程语法」**。
> 所以你学 JSON 的姿势应该是：**学它的规矩**（程序认什么、不认什么），
> **不是学怎么手写它**。

## 五、给验收用的：一眼扫出问题的清单

你不需要会写 JSON。你需要的是一眼看出「AI 写的这份能不能用」。
下面这份清单是把上面所有内容压成**验收动作**：

| # | 扫什么 | 出问题的样子 |
|---|---|---|
| 1 | **键是不是字符串** | 键是裸数字/没引号 → 程序取值对不上 |
| 2 | **`true` / `false` / `null` 的写法** | 写成 `True` / `False` / `None`（Python 习惯）→ 解析失败 |
| 3 | **有没有单引号** | `'name'` → 必挂 |
| 4 | **有没有注释** | `//` 或 `#` → 必挂 |
| 5 | **结尾有没有多逗号** | 最后一个字段后面还跟 `,` → 必挂 |
| 6 | **数字有没有被加引号** | `"age": "30"` → 算不了 |
| 7 | **该分层的地方分了没** | 明细和汇总混一个数组 → 没法逐条处理 |

**前 6 条都是「格式」层，看一眼就能判断；第 7 条是「设计」层，靠你的需求理解。**

## 六、两个你一定见过的真例子

学格式最有效的方式是看**结构长什么样**。这两个都是你在真实项目里会遇到的：

### 例子 1：Node 项目的 `package.json` —— 项目配置

```json
{
  "name": "my-app",
  "version": "0.1.0",
  "private": true,
  "engines": {
    "node": ">=22"
  },
  "scripts": {
    "test": "node --test",
    "start": "node src/index.js"
  }
}
```

**对照着看**（这就是前面那张表在实战里的样子）：

| 看到什么 | 说明 |
|---|---|
| 最外层 `{ }` | 一个**对象** = 一整份信息（这个项目的配置） |
| `"name": "my-app"` | 键 `"name"` → 值 `"my-app"`（字符串） |
| `"private": true` | 🔴 **全小写 `true`** —— 不是 Python 的 `True` |
| `"engines": { "node": ">=22" }` | **嵌套**：一个对象装在另一个对象里 |
| `"scripts": { ... }` | 又是一个嵌套对象，里面两行「键值对」 |
| 每行末尾 `,`，**最后一行没有** | 这就是第三节说的「不能有尾逗号」 |

> 💡 **这份文件通常是 AI 帮你生成的**，但它是**给程序读的**——
> `npm` 会读 `scripts.start` 去知道怎么启动你的项目。
> 如果 AI 把 `true` 写成 `True`、或最后一行多一个逗号，**程序直接起不来**。

### 例子 2：工具调用的参数 —— 这门课后面一直在用

模型要调用一个工具时，参数也是这么一份 JSON：

```json
{
  "tool": "search_reports",
  "arguments": {
    "keyword": "2026 上半年账单",
    "limit": 5,
    "exact_match": false
  }
}
```

**这份你到阶段 3 天天要打交道**，现在先认得结构：

| 看到什么 | 说明 |
|---|---|
| 最外层 `{ }` | 一整次调用 = 一个对象 |
| `"tool"` / `"arguments"` | **分层**：调用名一层，参数一层——两类信息分开 |
| `"keyword": "2026 上半年账单"` | 字符串必须带引号 |
| `"limit": 5` | 🔴 **数字不加引号**。写成 `"5"` 就成了字符串，程序可能报错 |
| `"exact_match": false` | 🔴 **全小写 `false`** |

> 💡 **为什么这件事值得现在就懂**：模型只输出文字，程序要靠这份 JSON 才知道
> 「到底调哪个工具、每个参数填什么」。**这就是「JSON 是让程序接住输出的接口」的现场证据**——
> 后面阶段 3 讲工具调用时，这个结构会原样再出现一次。

## 八、演练答案（先扫完再看）

### 演练 A 的错误（共 3 处）

| # | 位置 | 错在哪 | 后果 |
|---|---|---|---|
| 1 | `'name'` | **单引号** | `JSONDecodeError: Expecting property name enclosed in double quotes` |
| 2 | `"private": True` | **Python 写法**，JSON 要全小写 `true` | 解析失败 |
| 3 | `"start": "...",` 后面 | **尾逗号**（最后一行不该有逗号） | `JSONDecodeError: Illegal trailing comma` |

> ⚠️ **有个反直觉的点**：`"engines"` 排在 `"scripts"` 后面**不算错**。
> JSON **不要求键的顺序**，只要求语法正确。这点和「看起来该按顺序」的直觉不同。

### 演练 B 的错误（共 2 处）

| # | 位置 | 错在哪 | 后果 |
|---|---|---|---|
| 1 | `"limit": "5"` | **数字被加引号了**。`5` 是数字，`"5"` 是字符串 | 解析虽过，但程序拿到字符串去算大小会出错 |
| 2 | `"exact_match": false,` 后面 | **尾逗号**（`exact_match` 是最后一项了） | `JSONDecodeError: Illegal trailing comma` |

> 💡 注意 B 只有 2 处、A 有 3 处 —— **错得多不代表更简单**。
> `"limit": "5"` 这种**语法完全合法**，肉眼看不出毛病，只有对照「字段该不该是数字」才查得出来。

**✅ 扫对了的标准**：不是「感觉怪怪的」，而是能说出**报错类型** 或 **哪里不合需求** ＋ **怎么改**。
两处都能对上第三节的清单，这就是验收能力。

## 九、一句话收口

> **JSON 不是「一种像 Python 的东西」，它是「所有语言都认的一张表格」。**
>
> - 对的那半：`[ ]` = Python 列表 ✅
> - 漏的那半：`{ }` = Python 字典，**AI 输出里更常见** 🔴
> - 三处必须记住的严格性：**键要字符串** ｜ **只认双引号、无注释、无尾逗号** ｜ **`true`/`false`/`null` 全小写**
> - 两处特殊：**JSON 没有元组、没有集合、没有日期类型**（Python 有）
> - 一处容易漏：**数字不能加引号**。`5` 和 `"5"` 是两回事，语法都能过，但程序会算错
