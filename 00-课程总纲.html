一、这个课程要解决什么问题

本课程面向想系统学 AI 应用、但没有编程背景的人。

很多人已经能做出东西——用 AI 写代码、搭各种小工具——却讲不清「为什么这么做、还有没有别的做法、怎么权衡」。
能把做过的事用行业通用语言讲明白，本身就是一道门槛。

所以本课程不教写代码，教两件事：

  1. 成体系的概念认知 —— 能把做过的事用行业通用语言讲清楚
  2. 表达的完整度 —— 答得对不够，要能说清「为什么这么选」

前置说明：本课程默认学员不写代码。所有代码实现由 AI 完成，学员负责判断与验收。
这正是 AI 应用岗的真实工作方式。

二、8 阶段路线图

阶段 名称 核心问题
0 基础概念 大模型到底是什么？它能干什么、不能干什么？
1 Prompt 工程 怎么把要求说清楚，让它稳定照做？
2 RAG（检索增强） 资料太多塞不进去，怎么办？
3 Agent + 工具调用 怎么让它不光会说，还能动手做事？
4 多 Agent 协作 一件事太复杂，怎么拆给多个角色分工？
5 工程化 做出来了，怎么让它稳定、可观测、能上线？
6 垂直应用 真实行业里这些技术怎么落地？
7 求职实战 怎么把学过的东西讲清楚、讲得让人信？

每阶段固定三件套：本章导读 + 大白话讲义 + 章节小测与测验（题量5~20 题，按阶段难度定）。

铁律：

  • 测验正确率 < 80% 不进下一阶段
  • 同一概念错 2 次，退回重学那一节
  • 讲完一个概念停下等确认，不自动往下跑

三、阶段 0 知识点浓缩（一页速览）

# 概念 一句话 自测时会问什么
1 大模型本质 它是接话机器，不是查资料机器 「模型有记忆吗」→ 没有，记忆是外面存的
2 Token AI 的视力上限，也是它的计价器 「为什么不能让它读完我的大表」
3 上下文窗口 桌面就这么大，满了最早的纸就掉地上 「为什么聊久了它会忘」
4 幻觉 它在挑最顺的下一句，不是核对过的那句 「你怎么防幻觉」→ 给它材料，不是求它别编
5 四层手段 Prompt → RAG → Agent → 微调，能往上不往下 「这个需求你选哪个方案」——最高频考点
6 微调的边界 微调改的是风格，不是知识 「想让它记住公司制度用什么」→ RAG，不是微调
7 三条边界 模型不执行 / 没记忆 / 不知道自己错 「AI 怎么控制电脑的」→ 它只输出文字，外层程序执行

四层手段选择铁律（背下来）

能用 Prompt 解决的，不上 RAG；
能用 RAG 解决的，不上 Agent；
能用 Agent 解决的，绝对不上微调。

理由：每往下一层都更贵、更慢、更难维护。

六、怎么用这个课程

  1. 先读本章导读，知道这一阶段学什么
  2. 再读讲义，重点看被标粗的节
  3. 做测验，不用查资料，凭理解答
  4. 交答案，等批改 + 追问
  5. 过关才往下，不过关就重读对应小节

不懂直接说「这节没懂」，不要硬扛——讲义写给人看懂是出题方的活，看不懂是出题方的问题。

七、卡住了怎么办

卡住的时候：先翻 学员错题本.html——Scout 教学时会把你踩过的坑记进去。
那一页还附了各阶段的常见坑，供你预习用。

本页只讲一件事：本课程是主线，外部资料是参考书。
外部资料默认你会写代码、能开环境，也不做项目映射、没有测验和错题机制，
所以不要拿它替代本课程——它只在你想看「行业标准怎么表述某个概念」的时候有用。
