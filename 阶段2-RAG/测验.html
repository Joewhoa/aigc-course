Q7
【考 2.2】用五步说清 RAG 的完整流程，每步一句话。
考点：2.6 —— 这道题是高频考点，必须答对。

答偏在哪
「用 RAG」只说了知识库，而问题问的是「记忆」。
记忆 ≠ 知识库——只答 RAG 等于漏了一半。

根本区别（这一句是得分点）
· 知识库：对所有人一样的公共知识（产品手册、公司制度、FAQ）；组织统一维护；文档变了才更新
· 用户记忆每个人不同的私人信息（这个用户偏好简短回答、他是财务岗）；系统自动从对话里提取；每次交互都可能更新

加分（说出任一条）
· 记忆其实有三层：轨迹（单次任务）/ 用户长期记忆（跨会话）/ 业务状态（任务周期）
· ⭐ 反直觉结论：用户记忆通常不需要向量库——记忆只有几十到几百条直接塞进上下文更简单更准。这又是五问表第 2 问「塞得进就直接给」
· 失效后果不同：知识库答错是事实错；用户记忆搞错是把别人的信息给了你（隐私事故）
Q8

【考 2.2 + 2.5】两个小问，各答一句：

  1. 你的 RAG 系统回答很慢。排查时你先看哪一步？为什么？
  2. 一个财务对账系统要判断「两笔金额加起来是否相等」。这件事该交给模型还是交给代码？为什么？
考点：2.7 —— 要点是「改变了什么」＋「什么时候不用」。

改变了什么把检索从「管道里的一个固定环节」变成「Agent 手里的一件工具」
交给 ReAct 循环，由 Agent 自己决定搜几次、搜什么。
（记法它不需要新机制，就是把 Agent 的循环用在了检索上。）

什么时候不推荐（这是本题的重点，只说好处不给坏话要扣分）
· 问题直接、一段资料就能答 → 普通 RAG 就够
· 检索质量稳定、不需要 Agent 反复判断「够不够」
· 成本敏感时：Agentic RAG 多轮检索 = 多次模型调用 = 更贵更慢

收口句又是同一条铁律——能用简单方案就别上复杂的。
同事那句「更高级所以直接上」的问题在于它贵、慢，不是所有场景都划算。
Q9
【考 2.3】一个用 TF-IDF 做检索的财务对账系统。
请说明：为什么在这个场景下，TF-IDF 是够用的？
（提示：想想这类单据里的内容有什么特点）
考点：2.8 —— 这题是阶段 7「员工手册每季度更新」的题眼。

按这个顺序答（四步）
① 两条路径新政策进来走增量更新（当天生效）；每季度走一次全量整理。
② 变更走审核把知识库当代码库，每次变更当一个 PR——提议者提改动 → 审核者独立核证据 → 批准才合入 → 合入后才重建索引。两个 Agent 用不同家族模型（异源互审）。
③ 旧版要下线每块打版本号 + 生效/失效时间在检索阶段就过滤掉已失效的。
  （原因：旧政策还在库里，检索时可能和新版一起被召回，模型就会给出自相矛盾甚至过时的答案。）
④ 收口句索引是可重建的「派生物」，Git 里已审核的知识才是真正的来源。

⭐ 必答的一句（提示里问的就是这个）
「文件改了」≠「检索到新内容」——改完必须回到离线那三步：重新切块 → 重新向量化 → 重建索引。
只改文件不重建索引，是新手最常踩的一个坑。

加分多用户共享时检索必须按调用者权限过滤（一旦敏感内容进了上下文就很难不泄露）。
Q10
【考 2.4】RAG 有四种常见失效模式：检索没找到 / 检索错了 / 找到了但不看 / 找到太多。
请挑其中两种，各说出「表现是什么」和「怎么应对」。
考点：2.2（离线/在线）＋ 2.5（算力分工）—— 两小问各 0.5 分。

第 1 小问 · 回答很慢先看哪一步
先把五步分成两半
· 离线三步（切块 / 向量化 / 入库）= 建库时做一次 → 不影响每次响应速度
· 在线两步（检索 / 生成）= 每来一个问题都跑 → 慢只可能慢在这里

所以答先看在线那两步——最常见的原因是检索返回太多（收窄 top-k）或塞进上下文的资料太长。
（能说出「离线那三步不影响每次响应」就是满分；只答「换个更快的模型」= 没答到点上。）

第 2 小问 · 判断两笔金额相加是否相等
交给代码。理由是——答案是「确定的」，交给代码；答案是「模糊的」，交给模型。
金额相加必须 100% 准确，模型算数会出错；RAG 只负责把相关账单找出来递过去，不改变这条分工。
（真实做法RAG 找依据 → 代码算数 → 模型把结果说成人话。）
Q11

【考 2.6】「你的 Agent 怎么做记忆？」

有个回答是：「用 RAG 就行。」
请你指出他答偏在哪，并说清「知识库」和「用户记忆」的根本区别是什么。

考点：2.2。要点（五步，缺一步扣分）
① 切块：把长文档切成一段一段
② 向量化：把每段文字变成一串数字，意思相近的数字也相近
③ 入库：把这些数字存进能快速查找的地方（向量库）
④ 检索：把用户问题也向量化，找出最接近的 top 3～5 段
⑤ 生成：把检索到的片段和问题一起发给模型，并要求它只依据这些资料回答

加分补一句「工业级还会加混合检索（关键词 + 语义两路一起跑）和重排序」；
或补「①②③ 是离线建索引，④⑤ 是在线查索引」。
Q12

【考 2.7】有个同事说：「Agentic RAG 就是更高级的 RAG，效果更好，所以我们直接上它。」

请说明：Agentic RAG 到底改变了什么？ 并在什么情况下你不会推荐用它、为什么。

考点：2.3。要点（三层，缺一层扣分）
· 账单里的关键信息是「字面匹配」的——商户名、金额、日期、订单号这些不需要「理解意思」
· TF-IDF 靠词重叠算相似度，正好匹配这类需求；换成 Embedding 反而更慢更贵
· 所以这是按场景选工具，不是「用了过时技术」

⚠️ 上两轮都漏过这一层，注意别只答「词固定」就完事——必须说到「因为这些信息本身不需要语义理解」。

反面对照（说出这句更稳）如果要做一个员工手册问答——员工会用各种说法问同一件事（「年假怎么算」「休假天数规则」「带薪假期规定」说的其实是一回事）TF-IDF 就不够了，得上 Embedding。
Q13

【考 2.8】客户问你：「我们的员工手册每季度更新一次，怎么保证 AI 答的不是过时的内容？」

请给出你的方案。（提示：想想「文件改了」和「检索到新内容」中间还差什么）

考点：2.4。参考答案（任两种成立即可）
· 检索没找到：资料里明明有，它说没有。根因是切块切断关键信息、或用户用词差太远。
  对策：调整切块策略；用混合检索（关键词 + 向量一起）
· 检索错了：找到的是不相关段落。根因是相似度把「字面像但意思不同」的排前面。
  对策：加一层重排序（rerank）；加过滤条件（按时间、类别）
· 找到了但不看：资料递过去了，它还是自己编。根因是提示词没要求「只依据资料」。
  对策：补上约束 + 给出替代动作「资料未提及」
· 找到太多：塞了 20 段，噪音淹没有效信息。对策：限制 top-k 到 3～5 段；把最相关的排前面
Q14

【考 2.9】「RAG 和微调有什么区别？我该用哪个？」
请给出回答。

要求（三条都要做到）：

  1. 成段说，不要分点符号。就像当面回答一样。
  2. 分开说清两边：RAG 管什么、微调管什么——各自的适用场景都要提到。
  3. ⚠️ 结尾必须有一句收口总结。（这是最容易漏的一条——不是不知道，是答的时候想不起来用。写完回头检查一遍有没有这句。）
考点：2.9 —— ⚠️ 这条是本题的失分点，前两轮都缺收口句，务必自查。

一段可以照着说的示范
「这两个解决的其实是不同的问题。RAG 管的是『知不知道』——它把资料检索出来，在提问的时候一起递给模型，相当于给模型配了一本随时能翻的手册，知识本身留在外面，更新的时候换文件就行。微调管的是『怎么说话』——它是拿自己的数据再训练一下模型，改变的是输出的风格和格式习惯，不是给它装知识。

所以判断很简单：如果是我们的业务知识、内部文档、会变动的信息，用 RAG；如果是要求输出格式特别稳定，或者要用小模型替代大模型来省钱，才考虑微调。最常见的错误是拿微调去记业务知识——那样既不准，文档一更新还得重训。」

三个得分点（缺一扣）
① 成段，不列点
② 两边都说清：RAG 管知识（业务知识 / 会变的资料）；微调管风格习惯（＋ 小模型替代大模型省钱——这是工业界最主流用法，上两轮都漏了）
③ ⚠️ 收口句：「RAG 给的是知识，微调改的是风格和习惯。」
  听别人讲一段话，记住的往往是最后一句——没有收口句，前面说得再好也留不下印象。
